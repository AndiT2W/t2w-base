# Source: User Event Communication Vision 2026-06-29

## Metadata

- Date: 2026-06-29
- Type: user conversation
- Location: chat
- Status: active

## Summary

- In the end-state system, communication should be attached to the event itself.
- The event should become the central place where teammates can see what communication happened and what the current state is.

## Key Facts

- A general event note field is required.
- Outlook communication related to the event should eventually be aggregated into the event view.
- WhatsApp communication related to the event should eventually be aggregated into the event view.
- Other relevant communication channels should be attachable or aggregatable as well.
- The event should expose a shared communication history so every Time2Win team member can understand the latest situation without searching across tools.

## Implications For Project

- Event records should support a timeline or activity feed concept, not only static fields.
- Communication integration belongs to the end-state product vision, even if the first release only starts with notes or manual activity logging.
- The event should become the shared operational context for status, files, tasks, and communication.
